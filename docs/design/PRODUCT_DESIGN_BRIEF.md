# BudgetAnalytics — Product Design Brief

> Статус: **черновик на утверждение** (Task 0 — Product & UI Design Contract).
> Источник истины по возможностям — код backend на коммите `e746e35` (ветка `main`) и OpenAPI, сгенерированный из `backend/app/main.py`. Ничего из описанного ниже не реализовано во frontend: frontend ещё не начат.

## 1. Продукт

BudgetAnalytics — персональный финансовый ассистент для пользователей в Казахстане: учёт доходов и расходов, счета, категории, бюджеты, аналитика, депозиты, финансовые цели и AI-советник, который **объясняет проверенные данные, но не считает и не придумывает цифры** (`CLAUDE.md` §2.5, `backend/app/services/ai/prompts.py`).

Продукт **не** банк, не кредитный брокер и не брокерский терминал. Торговый функционал, котировки, ордера, портфели ценных бумаг — вне scope.

### Как использовать референс Tradernet
Берём: плотные, но читаемые таблицы с выравниванием чисел по правому краю; панель фильтров над таблицей с явными чипами активных фильтров; ясная иерархия «ключевой показатель → детализация»; табличные цифры.
Не берём: терминальную сложность, многооконность, стаканы, котировки, торговые действия, мелкий шрифт ради плотности.

## 3. Пользователи и задачи

| Задача пользователя | Модуль | Поддержка backend |
|---|---|---|
| Видеть финансовое положение за текущий месяц | Обзор | ✅ `GET /dashboard/overview` |
| Записать доход или расход | Транзакции | ✅ `POST /transactions` |
| Найти и исправить операцию | Транзакции | ✅ фильтры, `PATCH`, `DELETE` |
| Вести несколько счетов и карт, в т. ч. в разных валютах | Счета | ✅ валюта счёта фиксируется при создании |
| Ограничить траты по категории | Бюджеты | ✅ месячный лимит + `/utilization` |
| Понять, куда уходят деньги | Аналитика | ✅ summary, категории, 12 месяцев, сравнение месяцев |
| Оценить доход по вкладу | Депозиты | ✅ калькулятор и сохранённые вклады |
| Копить на цель | Цели | ✅ прогресс и нужный ежемесячный взнос (ручной учёт накоплений) |
| Получить объяснение и совет | AI-советник | ✅ отчёт и одиночный вопрос; ⬜ история чата |
| Загрузить выписку банка | Импорт | ✅ CSV/XLSX, предпросмотр, дедупликация; парсеры **не проверены на реальных выписках** |
| Восстановить пароль | Аутентификация | 🟧 нет backend |
| Получать уведомления | Уведомления | 🟧 нет backend |

Легенда статусов используется во всех документах:
- ✅ **BE** — поддерживается текущим backend.
- 🟦 **FE** — реализуемо только на стороне frontend (без изменений backend).
- 🟧 **BE-CHANGE** — требуется изменение backend.
- ⬜ **FUTURE** — предложение, вне v1.

## 4. Продуктовые принципы для дизайна

1. **Финансовая правда — на backend.** Frontend не пересчитывает суммы, проценты, остатки, прогресс и проценты по вкладам; он только форматирует строки Decimal из API (`CLAUDE.md` §9 «Do not let UI formatting become the source of financial truth»).
2. **Валюты не смешиваются.** Аналитика и обзор считаются в одной валюте за раз; суммы в разных валютах не конвертируются и не складываются (`backend/app/api/analytics.py` docstring). UI показывает переключатель валюты, а не «общий итог».
3. **Денежный поток ≠ баланс.** `net_cash_flow` — поток за период, не остаток на счёте (`SummaryResponse.note`). Подписи в UI обязаны это различать.
4. **Честность AI.** Каждый ответ AI показывает источник (`generated_by`: `llm` или `rules`), факты (`facts`), допущения и дисклеймеры. Никаких гарантий доходности или одобрения.
5. **Нет фиктивных возможностей.** Экраны без backend помечаются в макетах бейджем «Скоро» / «Требует backend» и не участвуют в основном прототипе как рабочие.
6. **Поддерживающий тон.** Без осуждения за долги и перерасход (`CLAUDE.md` §5 Phase 4 Response policy).

## 5. Информационная архитектура (верхний уровень)

```
Аутентификация (вне оболочки)
  ├─ Вход
  ├─ Регистрация
  ├─ Восстановление пароля        🟧
  └─ Новый пароль                 🟧
Приложение (оболочка: сайдбар + шапка)
  ├─ Обзор
  ├─ Транзакции ─┬─ Список
  │              ├─ Детали (drawer)
  │              ├─ Создание/редактирование (modal)
  │              └─ Импорт выписки (wizard) + история импортов
  ├─ Счета ──────┬─ Список
  │              └─ Детали счёта
  ├─ Категории ──┬─ Список (доходы/расходы)
  │              └─ Создание/редактирование (modal)
  ├─ Бюджеты ────┬─ Список
  │              ├─ Детали
  │              └─ Создание/редактирование (modal)
  ├─ Аналитика ──┬─ Обзор
  │              └─ Детальная аналитика
  ├─ Депозиты ───┬─ Список
  │              ├─ Детали
  │              └─ Калькулятор
  ├─ Цели ───────┬─ Список
  │              ├─ Детали
  │              └─ Создание/редактирование (modal)
  ├─ AI-советник ┬─ Чат (одиночные вопросы)
  │              └─ Финансовый отчёт
  ├─ Уведомления  🟧 (список, пустое состояние, детали)
  └─ Настройки ──┬─ Общие (профиль read-only)
                 ├─ Оформление 🟦
                 └─ Безопасность
```

Пункты сайдбара: Обзор, Транзакции, Счета, Категории, Бюджеты, Аналитика, Депозиты, Цели, AI-советник; в нижней группе — Уведомления, Настройки. Импорт — действие внутри «Транзакций» (решение на утверждение, см. `BACKEND_GAPS.md` §Решения).

Полный перечень экранов: [SCREEN_INVENTORY.md](SCREEN_INVENTORY.md). Связь с API: [API_TO_UI_MAPPING.md](API_TO_UI_MAPPING.md).

## 6. Ограничения инструментов дизайна

Figma-файл находится на тарифе **Starter**, место пользователя — View:
- максимум **3 страницы** в файле;
- **1 режим** на коллекцию переменных, поэтому Light и Dark — две отдельные коллекции с одинаковыми именами переменных;
- лимит вызовов Figma MCP: в прошлой сессии исчерпан примерно за 10 вызовов.

План размещения в Figma: [DESIGN_SYSTEM_SPEC.md §10](DESIGN_SYSTEM_SPEC.md#10-figma-implementation-blueprint).

## 7. Вне scope v1

Брокерские и торговые функции; open banking и подключение к банкам по API (у backend нет таких интеграций, `CLAUDE.md` запрещает запрашивать банковские пароли); долговой модуль (Phase 3 `CLAUDE.md`, не реализован); английская локализация; нативные мобильные приложения.

## 0. Общие правила для всех экранов приложения

**Оболочка.** Сайдбар (desktop), шапка с заголовком страницы, описанием и контекстными действиями, переключатель темы, кнопка профиля. Все экраны, кроме аутентификации, требуют access-токен (`Authorization: Bearer`).

**Общие состояния**
| Состояние | Поведение | Источник |
|---|---|---|
| Загрузка | Скелетоны в форме будущего контента (карточки, строки таблицы, график). Без спиннеров на весь экран. | 🟦 |
| 401 | Тихий `POST /auth/refresh`; если он не удался — переход на «Вход» с сообщением «Сессия истекла». Refresh одноразовый (ротация), параллельные запросы должны ждать один refresh. | ✅ `auth.py` refresh rotation |
| 403 | «Недостаточно прав» — встречается только при правке системных категорий. | ✅ |
| 404 | Экран «Не найдено»: запись удалена или принадлежит другому пользователю. Чужие записи всегда отдают 404, не 403. | ✅ `CLAUDE.md` tenant isolation |
| 422 | Ошибки валидации у полей: `detail[]` содержит `loc` и `msg` **на английском**, frontend показывает русский текст по `loc` и `type` (**G-10**). | ✅ + 🟦 |
| 429 | «Слишком много запросов, повторите через N с» — из заголовка `Retry-After`, который доступен через CORS. | ✅ |
| 5xx / сеть | Блок ошибки в секции, кнопка «Повторить» и `request_id` мелким шрифтом для поддержки. | ✅ `ErrorResponse.request_id` |
| Пусто | Иллюстрация-пиктограмма, одно предложение и главное действие. | 🟦 |
| Успех | Toast внизу справа (desktop) или вверху (mobile), 4 с; для удаления — без «Отменить», потому что у backend нет undo. | 🟦 |

**Деньги** приходят строками Decimal (например, `"450000.00"`) с полем `currency_code`; форматирование описано в [DESIGN_SYSTEM_SPEC.md §6](DESIGN_SYSTEM_SPEC.md#6-форматирование-чисел-дат-и-валют). **Даты и время** приходят в UTC, показываются в часовом поясе пользователя (параметр `tz`, по умолчанию `Asia/Almaty`).

## A. Аутентификация

### A-1 Вход — ✅
- **Назначение:** вход по e-mail и паролю.
- **Главное действие:** «Войти». **Вторичные:** «Создать аккаунт», «Забыли пароль?» (ведёт на A-3, помеченный «Скоро»).
- **Поля:** e-mail* (формат email), пароль* (не длиннее 1024 символов, без минимума на входе).
- **API:** `POST /auth/login` → `access_token`, `refresh_token`.
- **Состояния:**
  - 401 → «Неверный e-mail или пароль» (одно сообщение для обоих случаев);
  - 403 → «Аккаунт деактивирован»;
  - 429 → блокировка формы с таймером: лимиты 20 попыток в минуту на IP и 10 за 15 минут на аккаунт (`rate_limit.py:56-57`);
  - загрузка — кнопка в состоянии loading, поля заблокированы.
- **Валидация:** e-mail на клиенте, пустой пароль. Пароль не сохраняется и не логируется.
- **Адаптивность:** центрированная карточка 400 px; на mobile — на всю ширину с отступами 16.
- **Не поддерживается:** вход через соцсети или OTP (⬜); «Запомнить меня» — нет отдельной настройки, refresh живёт 7 дней (`REFRESH_TOKEN_EXPIRE_DAYS`).

### A-2 Регистрация — ✅
- **Главное действие:** «Создать аккаунт» (сразу авторизует: ответ 201 содержит токены).
- **Поля:** имя* (1–255), e-mail*, пароль* (8–128), подтверждение пароля (только 🟦 на клиенте).
- **API:** `POST /auth/register`.
- **Состояния:** 409 → «Этот e-mail уже зарегистрирован»; 422 → ошибки полей; 429 → 10 регистраций в час на IP.
- **Не поддерживается:** выбор валюты по умолчанию при регистрации — backend ставит KZT, поля в API нет (**G-4**); согласие с политикой — нет хранения согласий (🟧 **G-24**); подтверждение e-mail (🟧).

### A-3 Восстановление пароля — 🟧 BE-CHANGE
- **Назначение (предложение):** ввод e-mail и отправка ссылки.
- **API:** нет. Требуется отправка e-mail и одноразовые токены (**G-1**).
- **Дизайн:** форма и экран «Письмо отправлено» с нейтральным текстом, не раскрывающим существование аккаунта. В макете — бейдж «Требует backend». В прототипе — тупиковый экран.

### A-4 Новый пароль — 🟧 BE-CHANGE
- **Поля (предложение):** новый пароль (8–128 — по аналогии с `ChangePasswordRequest`), подтверждение.
- **Состояния:** «Ссылка недействительна или истекла», «Пароль изменён — войдите снова».
- **API:** нет (**G-1**).

## D. Обзор

### D-1 Обзор — ✅
- **Назначение:** финансовое положение за текущий месяц в одной валюте.
- **Главное действие:** «Добавить транзакцию». **Вторичные:** переключатель валюты (если у пользователя счета в нескольких валютах), «Все транзакции», переход в бюджеты и депозиты.
- **Данные** (`GET /dashboard/overview`):
  - `current_balance` — сумма активных счетов **в выбранной валюте**; `null`, если в этой валюте счетов нет → «Нет счетов в {валюте}»;
  - `accounts[]`;
  - `monthly_income`, `monthly_expenses` (нетто: расходы − возвраты), `monthly_net_cash_flow`;
  - `budgets[]` со статусом текущего месяца;
  - `indicators`: `savings_rate`, `expense_to_income_percent`, `income_change_percent`, `expense_change_percent`, `average_monthly_expenses_3m`, `emergency_fund_months`, `budgets_exceeded`/`budgets_total`, `deposits_principal`, `deposits_expected_interest`;
  - `notes[]` — на английском (**G-10**), в UI заменяются русскими подсказками 🟦.
- **Дополнительно:**
  - последние операции — `GET /transactions?limit=5`;
  - денежный поток по месяцам — `GET /analytics/monthly?year=YYYY`;
  - структура расходов — `GET /analytics/category-breakdown?kind=expense` (текущий месяц по умолчанию).
- **Состояния:**
  - пусто (нет транзакций и счетов) → онбординг из 3 шагов: «Добавьте счёт», «Добавьте транзакцию», «Импортируйте выписку»;
  - `null`-показатели → «—» с подсказкой (например, «Норма сбережений не считается без доходов»).
- **Валидация:** не требуется. Период фиксирован — текущий месяц (`OverviewResponse.month`); выбора периода на обзоре **нет** (backend не принимает период).
- **Адаптивность:** 4 метрики в ряд → 2×2 на tablet → вертикальная лента на mobile; график денежного потока → горизонтальный скролл на mobile запрещён, вместо него последние 6 месяцев.
- **Не поддерживается:** суммарный баланс во всех валютах с конвертацией (⬜ — backend не конвертирует намеренно).

## T. Транзакции

### T-1 Список транзакций — ✅
- **Главное действие:** «Добавить транзакцию». **Вторичные:** «Импорт выписки» (I-1), фильтры, сброс фильтров, открыть детали.
- **Данные:** `GET /transactions` → `items[]`, `total`, `limit`, `offset`.
  - Строка: дата, описание, категория (имя — из `GET /categories`, в списке только `category_id`, **G-7**), счёт (имя — из `GET /accounts`), тип, сумма со знаком и валютой.
- **Фильтры (поддерживаются backend):** период `start_date`/`end_date` (включительно), категория, счёт, банк, тип, валюта, сумма от/до, поиск (**только по описанию**, без учёта регистра).
- **Сортировка:** только «новые сначала» (`transaction_date desc, id desc`). Сортировка по колонкам **не поддерживается** (**G-7**) — в таблице нет кликабельных заголовков.
- **Пагинация:** `limit` 1–200 (по умолчанию 20), `offset`. UI: 20/50/100 на страницу, «Показано 1–20 из N».
- **Состояния:**
  - пусто без фильтров → «Пока нет операций» + «Добавить» / «Импорт»;
  - пусто с фильтрами → «Ничего не найдено» + «Сбросить фильтры»;
  - 422 на неверный диапазон суммы — валидация на клиенте до запроса.
- **Адаптивность:** таблица (desktop) → таблица без колонок «Банк» и «Тип» (tablet) → карточки, сгруппированные по дате (mobile); фильтры на mobile — в нижнем листе.

### T-2 Детали транзакции — ✅ (drawer справа, на mobile — полный экран)
- **Данные:** `GET /transactions/{id}` → все поля + `category_name`, `bank_name` (`"—"`, если нет), `created_at`/`updated_at`.
- **Действия:** «Редактировать» (T-3), «Удалить» (диалог подтверждения → `DELETE`, 204).
- **Состояния:** 404 → «Операция не найдена».
- **Не поддерживается:** вложения и чеки, заметки отдельно от описания, история изменений (⬜).

### T-3 Создание / редактирование транзакции — ✅ (modal; на mobile — полноэкранный лист)
- **Поля:**
  - тип* (Расход / Доход / Возврат / Перевод: поступление / Перевод: списание);
  - сумма* (> 0, до 16 знаков до запятой и 2 после);
  - дата и время*;
  - категория* — список фильтруется `GET /categories?kind=income|expense` по выбранному типу;
  - счёт (опционально);
  - валюта — по умолчанию валюта счёта, при выбранном счёте поле заблокировано;
  - банк (опционально, `GET /banks`);
  - описание (≤ 500).
- **API:** `POST /transactions` (201), `PATCH /transactions/{id}` (200).
- **Бизнес-правила backend:**
  - категория должна подходить к типу, иначе 400 «Category … cannot be used for …»;
  - валюта должна совпадать с валютой счёта, иначе 400;
  - чужие или несуществующие категория, счёт, банк → 400 «… not found».
- **UX-правило 🟦:** при смене типа категория сбрасывается, если она не подходит.
- **Состояния:** loading кнопки; ошибки у полей; успех → toast «Операция сохранена», закрытие модалки, обновление списка.
- **Ограничения:**
  - перевод между своими счетами — это **две отдельные операции** (`transfer_out` и `transfer_in`), backend не связывает их (**G-8**);
  - архивные счета нужно скрыть из выбора (🟦), потому что backend их не блокирует (**G-9**).

## I. Импорт выписки (дополнительно, внутри «Транзакций»)

### I-1 Мастер импорта — ✅
- **Шаги:**
  1. Выбор банка (`GET /imports/banks`: `code`, `name`, `formats`, `verified`) и счёта (опционально).
  2. Загрузка файла (.csv/.xlsx, до 5 МБ, до 5000 строк) → `POST /imports/{bank}/preview` (multipart).
  3. Предпросмотр: сводка (`total`/`valid`/`invalid`/`duplicate` строки, период) и таблица строк со статусами `valid` / `invalid` (с причиной) / `duplicate` / `possible_duplicate`; пагинация `GET /imports/{id}/rows?status=`.
  4. Подтверждение: исключить строки, флажок «Импортировать возможные дубликаты» → `POST /imports/{id}/commit` → `imported`, `skipped`.
- **Обязательная пометка:** если `verified_parser=false` — предупреждение «Формат выписки этого банка ещё не проверен на реальных файлах. Внимательно проверьте строки перед импортом.» (**G-19**).
- **Ошибки:** 413 — файл слишком большой; 415 — неподдерживаемый тип; 409 — повтор подтверждения; предпросмотр истекает через 24 ч (`expires_at`), после — «Срок предпросмотра истёк, загрузите файл заново».
- **Отмена:** `DELETE /imports/{id}` (только для предпросмотра).

### I-2 История импортов — ✅
- `GET /imports` (пагинация): файл, банк, статус (`preview` / `committed` / `failed` / `cancelled` / `expired`), строки, период, дата. Для `failed` показывается безопасное `error_message`.

## AC. Счета

### AC-1 Список счетов — ✅
- **Главное действие:** «Добавить счёт» (modal). **Вторичные:** «Показать архивные» (`include_archived=true`), открыть детали.
- **Данные:** `GET /accounts` (массив без пагинации) — имя, тип (наличные / текущий / карта / сберегательный / кредитная карта / другое), валюта, банк, последние 4 цифры, баланс.
  - Баланс = начальный остаток + поступления − списания после даты начального остатка (вычисляет backend).
  - Группировка по валюте 🟦; итог по каждой валюте 🟦 — **только** если `GET /dashboard/overview?currency=X` (там `current_balance`), а не сумма на клиенте.
- **Форма счёта:** имя* (1–100), тип*, валюта (по умолчанию валюта пользователя; **после создания не меняется**), банк, последние 4 цифры (`^[0-9]{4}$`), начальный остаток (может быть отрицательным для долга), дата начального остатка.
- **Состояния:** пусто → «Добавьте первый счёт»; 409 при удалении счёта с операциями → предложить «Архивировать».
- **Безопасность (подсказка в форме):** «Никогда не вводите полный номер карты, CVV или PIN».

### AC-2 Детали счёта — ✅
- **Данные:** `GET /accounts/{id}` + операции `GET /transactions?account_id={id}`.
- **Действия:** редактировать (кроме валюты), архивировать / разархивировать (`PATCH is_archived`), удалить (только без операций, иначе 409).
- **Не поддерживается:** динамика баланса по дням (⬜ **G-14**); аналитика по одному счёту — `/analytics/*` не фильтрует по счёту (**G-14**).

## C. Категории

### C-1 Список категорий — ✅
- **Вкладки:** «Расходы» (`?kind=expense`), «Доходы» (`?kind=income`). Категории вида `any` видны в обеих вкладках с меткой «Любой тип».
- **Данные:** имя, цвет, иконка, тип, `is_system`. Системные категории (16 по умолчанию) — с замком, только чтение.
- **Действия:** создать, редактировать и удалить свою категорию. Удаление используемой категории → 409 «Категория используется в операциях или бюджетах».

### C-2 Создание / редактирование категории — ✅ (modal)
- **Поля:**
  - имя* (2–100, уникально среди видимых, иначе 409 — включая совпадение с системной);
  - цвет (`#RRGGBB`) — палитра из 12 цветов (набор 🟦);
  - иконка (slug `^[a-z0-9-]+$`) — выбор из фиксированного набора 🟦, совпадающего с иконками системных категорий: `shopping-cart, utensils, car, home, wifi, heart, shirt, book, film, gift, credit-card, dots, briefcase, plus, repeat, wallet` (+ дополнительные — решение дизайна);
  - тип (расход / доход / любой).
- **Правило:** смена типа на несовместимый с существующими операциями → 409 (`categories.py::_ensure_kind_fits_existing`).

## B. Бюджеты

### B-1 Список бюджетов — ✅ (с оговоркой **G-6**)
- **Данные:** `GET /budgets` (пагинация) — название, лимит, валюта, категория (или «Все расходы»).
- **Использование текущего месяца:**
  - либо `GET /dashboard/overview` → `budgets[]` (только бюджеты в выбранной валюте, текущий месяц, одним запросом);
  - либо `GET /budgets/{id}/utilization` для каждого бюджета (N запросов).
- **⚠ Запрещено** использовать `progress`, `remaining`, `is_exceeded`, `spent` из `GET /budgets` и `GET /budgets/{id}`: они считаются из устаревшего ручного поля `spent` (`api/budget.py:47-56`) (**G-6**).
- **Отображение:** прогресс-бар; ≥ 80 % — предупреждение (порог — решение дизайна 🟦, backend его не задаёт), > 100 % — «Превышен на X» (`is_exceeded`). Цвет не единственный носитель смысла: есть текст и иконка.
- **Пусто:** «Создайте первый бюджет».

### B-2 Детали бюджета — ✅
- **Данные:** `GET /budgets/{id}` (только метаданные) + `GET /budgets/{id}/utilization?month=YYYY-MM` (выбор месяца: лимит, потрачено = расходы − возвраты, остаток, процент, превышен) + операции месяца по категории `GET /transactions?category_id=&start_date=&end_date=&transaction_type=expense`.
- **Действия:** изменить, удалить (подтверждение).
- **Не поддерживается:** история по месяцам одним запросом (нужно N вызовов `/utilization`) (**G-6**); перенос остатка (⬜ **G-22**).

### B-3 Создание / редактирование бюджета — ✅ (modal)
- **Поля:** название* (2–100), месячный лимит* (> 0), валюта (по умолчанию валюта пользователя), категория (опционально — только `expense`/`any`; доходная → 400).
- **Не показывать** устаревшее поле `spent`.

### AN-1 Обзор аналитики — ✅
- **Фильтры:** период (пресеты «Этот месяц», «Прошлый месяц», «3 месяца», «Год», «Свой период» → `date_from`/`date_to` включительно), валюта.
- **Данные:**

### AN-2 Детальная аналитика — ✅
- **Данные:**
  - `GET /analytics/category-breakdown?kind=expense|income` (сумма, доля %, число операций);
  - `GET /analytics/income`, `GET /analytics/expenses`, `GET /analytics/savings-rate`;
  - таблица категорий с переходом в T-1 с фильтром категории и периода 🟦.
- **Не поддерживается:** разбивка по неделям и дням, по счёту или банку, тренды категорий во времени одним запросом, прогноз (**G-14**; legacy `/analytics/forecast` deprecated и не используется).

## DP. Депозиты

### DP-1 Список депозитов — ✅
- **Данные:** `GET /deposits` (пагинация) — банк (имя из `GET /banks`), сумма, ставка (номинальная), ГЭСВ (как указал банк), капитализация, даты, `maturity.interest`, `maturity.maturity_amount` (расчёт backend).
- **Итог:** `indicators.deposits_principal` и `deposits_expected_interest` из обзора (в одной валюте).
- **Действия:** «Добавить депозит», «Калькулятор».

### DP-2 Детали депозита — ✅
- **Данные:** `GET /deposits/{id}` → `maturity` (`term_days`, `capitalization_periods`, `stub_days`, `interest`, `maturity_amount`, `effective_annual_rate`) + `assumptions[]` (на английском — перевод 🟦, **G-10**).
- **Действия:** изменить, удалить.
- **Обязательно:** различать «Номинальная ставка» и «ГЭСВ (по данным банка)»; подпись «Оценка; расчёт банка может отличаться».

### DP-3 Калькулятор депозита — ✅
- **Поля:**
  - сумма* (> 0);
  - валюта (по умолчанию KZT);
  - номинальная ставка* (0–100 %);
  - капитализация (нет / ежемесячно / ежеквартально / ежегодно);
  - дата начала*;
  - срок: **ровно одно** из «дата окончания» или «срок в месяцах» (1–600) — переключатель 🟦.
- **API:** `POST /deposits/calculate` (ничего не сохраняет).
- **Результат:** доход, сумма к концу срока, эффективная годовая ставка (`null` без капитализации), дней, периодов капитализации, дней «хвоста», допущения.
- **Действие:** «Сохранить как депозит» → форма депозита (modal из DP-1) с предзаполнением; нужен банк (`POST /deposits` требует `bank_id`). Срок в месяцах не сохраняется: в форму подставляется `maturity_date` из ответа калькулятора как `end_date` 🟦.
- **Форма депозита (modal в DP-1 и DP-2):** банк* (`GET /banks`), сумма* (> 0), валюта (по умолчанию валюта пользователя), номинальная ставка* (0–100), ГЭСВ (0–1000, опционально, хранится как есть), капитализация, дата начала*, дата окончания* (позже начала).
- **Не поддерживается:** пополнения, снятия, налоги, досрочное расторжение (явно перечислено в допущениях backend).

## G. Финансовые цели

### G-1 Список целей — ✅
- **Данные:** `GET /goals` — название, цель, накоплено, прогресс % (может быть > 100), осталось, «достигнута», месяцев до срока, нужный ежемесячный взнос (равные части, без процентов).

### G-2 Детали цели — ✅
- **Данные:** `GET /goals/{id}`.
- **Действия:** «Обновить накопления» (`PATCH saved_amount`), редактировать, удалить.
- **Подпись:** «Накопления вводятся вручную и не связаны со счетами» (**G-13**).
- **Не поддерживается:** история пополнений, привязка к счёту, автоматический учёт (⬜ **G-13**).

### G-3 Создание / редактирование цели — ✅ (modal)
- **Поля:** название* (1–100, уникально → 409), целевая сумма* (> 0), уже накоплено (≥ 0), валюта (по умолчанию валюта пользователя; **меняется только при создании** — в `GoalUpdate` поля валюты нет), целевая дата (опционально, можно очистить).

## AI. AI-советник

### AI-1 Чат — ✅ (одиночные вопросы) / ⬜ (история)
- **Поле:** вопрос* (3–500 символов). **API:** `POST /advisor/ask`.
- **Ответ:** `answer.answer` (до 2000), `evidence` (id фактов → раскрываемый список «На чём основан ответ» из `facts[]`), `assumptions`, `needs_more_data`, `follow_up_question` (подсказка-чип), `disclaimers[]`, метка источника: «AI» (`generated_by=llm`) или «Правила» (`rules`, с причиной `fallback_reason`), `as_of`.
- **Ограничения:**
  - каждый вопрос независим: backend не хранит историю и не передаёт контекст прошлых сообщений → история диалога видна только в текущей сессии браузера 🟦 и пропадает после перезагрузки (**G-12**);
  - лимит 30 запросов в час (insights и ask вместе) и дневной лимит токенов → 429 или ответ из правил с `fallback_reason=limit_reached`.
- **Предупреждение в поле ввода:** «Не указывайте номера карт, ИИН и пароли» (backend дополнительно вычищает их, `advisor.py` docstring).

### AI-2 Финансовый отчёт — ✅
- **API:** `POST /advisor/insights` → `report.summary`, `insights[]` (по областям), `recommendations[]` (приоритет, «касается инвестиций»), `risks[]` (серьёзность), `assumptions`, `data_gaps`, `facts`, `disclaimers`.
- **Действие:** «Сформировать отчёт» — это POST, отчёт не сохраняется; повторное формирование тратит лимит.
- **Не поддерживается:** сохранённые отчёты и экспорт в PDF (⬜).

## S. Настройки

### S-1 Общие — ✅ (только чтение) / 🟧 (редактирование)
- **Данные:** `GET /auth/me` → имя, e-mail, дата регистрации.
- **Редактирование имени и e-mail:** API нет (**G-3**).
- **Валюта по умолчанию:** не возвращается в `/auth/me` и не меняется (**G-4**); показывать «KZT» как факт нельзя, пока backend не вернёт поле.
- **Часовой пояс:** хранится только на клиенте 🟦 и передаётся в `tz` (**G-17**).

### S-2 Оформление — 🟦
Тема: Светлая / Тёмная / Как в системе — в `localStorage`. Язык — только русский (v1).

### S-3 Безопасность — ✅ частично
- **Сменить пароль** — `POST /auth/change-password` (старый пароль ≤ 1024, новый 8–128). После успеха **все сессии завершаются** → перейти на «Вход» с сообщением «Пароль изменён. Войдите снова». Ошибки: 400 — неверный текущий пароль; 429 — 5 попыток в час.
- **Выйти на всех устройствах** — `POST /auth/logout-all` (подтверждение).
- **Выйти** — `POST /auth/logout` с refresh-токеном (идемпотентно).
- **Не поддерживается:** список активных сессий (**G-18**), 2FA (⬜), удаление аккаунта и экспорт данных (**G-11**).

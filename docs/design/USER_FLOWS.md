# User Flows

> Экраны — коды из [SCREEN_INVENTORY.md](SCREEN_INVENTORY.md); API — из [API_TO_UI_MAPPING.md](API_TO_UI_MAPPING.md). Пути без префикса `/api/v1`.
> Для каждого сценария: точка входа → шаги → вызовы API → успех → сбои и восстановление.
> Общее восстановление при 401 (тихий refresh → вход) и 429 (таймер `Retry-After`) действует во всех сценариях и далее не повторяется.

---

## F1. Регистрация и вход

**Вход в сценарий:** открытие приложения без сессии → A-1.

### F1a Регистрация
| # | Действие | Экран | API |
|---|---|---|---|
| 1 | «Создать аккаунт» на A-1 | A-2 | — |
| 2 | Ввод имени, e-mail, пароля, подтверждения; клиентская проверка (8–128, совпадение) | A-2 | — |
| 3 | «Создать аккаунт» | A-2 (loading) | `POST /auth/register` |
| 4 | Сохранение токенов, переход | D-1 (пустой, онбординг) | `GET /dashboard/overview`, `GET /auth/me` |

**Сбои:**
- 409 → ошибка у поля e-mail и ссылка «Войти»;
- 422 → ошибки полей;
- 429 → «Слишком много регистраций с этого адреса, попробуйте позже».

### F1b Вход
| # | Действие | Экран | API |
|---|---|---|---|
| 1 | Ввод e-mail и пароля | A-1 | — |
| 2 | «Войти» | A-1 (loading) | `POST /auth/login` |
| 3 | Переход в последний открытый раздел или на Обзор 🟦 | D-1 | `GET /dashboard/overview` |

**Сбои:**
- 401 → «Неверный e-mail или пароль», пароль очищается, e-mail остаётся;
- 403 → «Аккаунт деактивирован»;
- 429 → кнопка заблокирована с таймером.

### F1c «Забыли пароль?» — 🟧
A-1 → A-3: форма отображается с плашкой «Восстановление пароля пока недоступно». Отправка не выполняет запрос. Это тупик прототипа до реализации **G-1**.

## F2. Обзор → детали транзакции

**Вход в сценарий:** D-1, блок «Последние операции».

| # | Действие | Экран | API |
|---|---|---|---|
| 1 | Открытие обзора | D-1 | `GET /dashboard/overview`, `GET /transactions?limit=5`, `GET /categories`, `GET /accounts` |
| 2 | Клик по операции | T-2 (drawer поверх D-1) | `GET /transactions/{id}` |
| 2a | или «Все операции» | T-1 | `GET /transactions?limit=20&offset=0` |
| 3 | Клик по строке в T-1 | T-2 | `GET /transactions/{id}` |
| 4 | Закрытие drawer (Esc, крестик, клик по фону) — возврат с сохранением фильтров и позиции | T-1 / D-1 | — |

**Сбои:**
- 404 (операция удалена в другой вкладке) → drawer «Операция не найдена» и обновление списка;
- сеть → ошибка в drawer с «Повторить».

## F3. Создание и редактирование транзакции

**Точки входа:** кнопка «Добавить транзакцию» (шапка D-1, T-1), «Редактировать» в T-2.

### F3a Создание
| # | Действие | Экран | API |
|---|---|---|---|
| 1 | «Добавить транзакцию» | T-3 (modal) | `GET /accounts`, `GET /banks` (кэш) |
| 2 | Выбор типа (по умолчанию «Расход») | T-3 | `GET /categories?kind=expense` |
| 3 | Сумма, дата и время (по умолчанию «сейчас» в `tz`), категория, счёт (валюта подставляется и блокируется), описание | T-3 | — |
| 4 | Смена типа на «Доход» → категория сбрасывается, если она расходная | T-3 | `GET /categories?kind=income` |
| 5 | «Сохранить» | T-3 (loading) | `POST /transactions` с суммой строкой и датой с явным смещением |
| 6 | Toast «Операция добавлена», закрытие, обновление списка и метрик | T-1 / D-1 | повтор GET затронутых данных |

### F3b Редактирование
T-2 → «Редактировать» → T-3 с данными → `PATCH /transactions/{id}` (только изменённые поля) → toast → обновлённый T-2.

### F3c Удаление
T-2 → «Удалить» → диалог «Удалить операцию на 12 500,00 ₸? Действие нельзя отменить» → `DELETE /transactions/{id}` (204) → закрытие drawer и toast.

**Сбои:**
- 400 «cannot be used for …» → ошибка у поля категории: «Категория не подходит для этого типа операции»;
- 400 «Currency must match the account's currency» → ошибка у валюты;
- 400 «Account/Category/Bank not found» → обновить справочники и показать «Счёт недоступен, выберите другой»;
- 422 → у полей;
- при закрытии модалки с несохранёнными изменениями → подтверждение «Отменить изменения?» 🟦.

## F4. Создание и управление счётом

**Вход в сценарий:** AC-1 → «Добавить счёт».

| # | Действие | Экран | API |
|---|---|---|---|
| 1 | Форма: имя, тип, валюта (по умолчанию KZT — см. **G-4**), банк, последние 4 цифры, начальный остаток, дата остатка | AC-1 modal | `GET /banks` |
| 2 | Предупреждение у валюты: «Валюту нельзя изменить после создания» | — | — |
| 3 | «Создать» | — | `POST /accounts` |
| 4 | Карточка счёта в списке с балансом = начальный остаток | AC-1 | `GET /accounts` |
| 5 | Открытие счёта | AC-2 | `GET /accounts/{id}`, `GET /transactions?account_id=` |
| 6 | Редактирование (без валюты) | AC-2 modal | `PATCH /accounts/{id}` |
| 7a | «Архивировать» → скрыт из списка и из выбора в формах 🟦 | AC-1 | `PATCH {is_archived:true}` |
| 7b | «Удалить» | диалог | `DELETE /accounts/{id}` |

**Сбои:**
- 409 при удалении → «На счёте есть операции. Архивируйте его вместо удаления» + кнопка «Архивировать»;
- 422 у `last4` → «Только 4 цифры»;
- «Bank not found» (422) → обновить список банков.

## F5. Создание и управление бюджетом

**Вход в сценарий:** B-1 → «Создать бюджет»; или D-1 → блок бюджетов.

| # | Действие | Экран | API |
|---|---|---|---|
| 1 | Форма: название, месячный лимит, валюта, категория (только расходные и `any`) | B-3 | `GET /categories?kind=expense` |
| 2 | «Создать» | — | `POST /budgets` |
| 3 | Карточка с использованием текущего месяца | B-1 | `GET /budgets` + `GET /dashboard/overview` (или `/utilization` по каждому) |
| 4 | Открытие бюджета, выбор месяца | B-2 | `GET /budgets/{id}`, `GET /budgets/{id}/utilization?month=` |
| 5 | Операции бюджета за месяц | B-2 | `GET /transactions?category_id=&start_date=&end_date=` |
| 6 | Изменение или удаление | B-3 / диалог | `PATCH` / `DELETE /budgets/{id}` |

**Сбои:**
- 400 «income category» → «Бюджет ограничивает расходы — выберите расходную категорию»;
- бюджет в валюте, отличной от выбранной на обзоре, не появляется в `overview.budgets` → в B-1 использовать `/utilization`.

## F6. Просмотр аналитики

**Вход в сценарий:** сайдбар → «Аналитика», или клик по графику на D-1.

| # | Действие | Экран | API |
|---|---|---|---|
| 1 | Открытие: период «Этот месяц», валюта по умолчанию | AN-1 | `GET /analytics/summary`, `GET /analytics/comparison`, `GET /analytics/monthly?year=` |
| 2 | Смена периода → все виджеты периода перезапрашиваются; `monthly` зависит только от года | AN-1 | те же |
| 3 | Смена валюты (список из валют счетов пользователя 🟦) | AN-1 | те же с `currency=` |
| 4 | «Подробнее о категориях» | AN-2 | `GET /analytics/category-breakdown?kind=`, `/income`, `/expenses`, `/savings-rate` |
| 5 | Клик по категории → операции с фильтром | T-1 | `GET /transactions?category_id=&start_date=&end_date=` |

**Сбои:**
- пустой период → нули, `savings_rate=null` → «Нет доходов за период — норма сбережений не рассчитывается»;
- неверный `tz` → 422 (frontend передаёт только валидные IANA-имена);
- `date_from > date_to` блокируется на клиенте.

## F7. Создание и отслеживание финансовой цели

**Вход в сценарий:** G-1 → «Новая цель».

| # | Действие | Экран | API |
|---|---|---|---|
| 1 | Форма: название, целевая сумма, уже накоплено, валюта, дата | G-3 | — |
| 2 | «Создать» | — | `POST /goals?tz=` |
| 3 | Карточка: прогресс, осталось, месяцев до срока, нужно в месяц | G-1 | `GET /goals?tz=` |
| 4 | Открытие цели | G-2 | `GET /goals/{id}?tz=` |
| 5 | «Обновить накопления» → ввод новой **итоговой** суммы накоплений (не пополнения!) | G-2 modal | `PATCH /goals/{id} {saved_amount}` |
| 6 | При `is_reached=true` → состояние «Цель достигнута» | G-2 | — |

**Сбои:**
- 409 → «Цель с таким названием уже есть»;
- 400 «Unknown currency»;
- 422 при нулевой цели.

**UX-риск:** пользователь может ожидать «Пополнить на N». API принимает только итоговую сумму, поэтому поле подписывается «Сейчас накоплено» (**G-13**).

## F8. Калькулятор депозита

**Вход в сценарий:** DP-1 → «Калькулятор» или сайдбар → Депозиты → вкладка «Калькулятор».

| # | Действие | Экран | API |
|---|---|---|---|
| 1 | Ввод суммы, ставки, капитализации, даты начала, срока (переключатель «Дата окончания / Срок в месяцах») | DP-3 | — |
| 2 | «Рассчитать» (явная кнопка, без расчёта на каждое нажатие клавиши: расчёт делает backend) | DP-3 | `POST /deposits/calculate` |
| 3 | Результат: доход, итоговая сумма, эффективная ставка, дата окончания, допущения | DP-3 | — |
| 4 | «Сохранить как депозит» → форма с банком | DP-1 modal | `GET /banks`, `POST /deposits` |
| 5 | Депозит в списке | DP-1 | `GET /deposits` |

**Сбои:**
- 422 «Provide exactly one of end_date or term_months» → не должно возникать: переключатель допускает только одно поле;
- ставка > 100 → 422 у поля;
- `end_date ≤ start_date` → у поля.

**Обязательный текст:** «Расчёт — оценка при номинальной ставке, ACT/365. Пополнения, снятия, налоги и досрочное расторжение не учитываются; расчёт банка может отличаться.» (перевод `ASSUMPTIONS`, `schemas/deposits.py:22`).

## F9. Вопрос AI-советнику

**Вход в сценарий:** сайдбар → AI-советник (AI-1); или «Спросить AI» на D-1 🟦.

| # | Действие | Экран | API |
|---|---|---|---|
| 1 | Подсказки-вопросы (статический набор 🟦: «Куда уходит больше всего денег?», «Хватит ли подушки безопасности?») | AI-1 | — |
| 2 | Ввод вопроса (3–500 символов; счётчик) | AI-1 | — |
| 3 | «Отправить» → индикатор «Анализирую ваши данные…» | AI-1 | `POST /advisor/ask?tz=&currency=` |
| 4 | Ответ: текст, «На чём основано» (факты), допущения, дисклеймеры, метка «AI» или «Правила» | AI-1 | — |
| 5 | Если `follow_up_question` есть → чип, по клику — новый вопрос (**без контекста прошлого**, **G-12**) | AI-1 | `POST /advisor/ask` |
| 6 | Вкладка «Отчёт» → «Сформировать» | AI-2 | `POST /advisor/insights` |

**Сбои:**
- `generated_by=rules` + `fallback_reason`:
  - `disabled` → «AI отключён, ответ подготовлен по правилам»;
  - `limit_reached` → «Дневной лимит AI исчерпан…»;
  - `provider_error` → «AI временно недоступен…»;
  - `invalid_output` → «Ответ AI не прошёл проверку…»;
- 429 → «Лимит запросов к советнику: 30 в час»;
- 422 → «Вопрос должен быть от 3 до 500 символов»;
- `needs_more_data=true` → подсказка «Добавьте операции или счета, чтобы ответ был точнее».

## F10. Импорт выписки

**Вход в сценарий:** T-1 → «Импорт выписки»; онбординг D-1.

| # | Действие | Экран | API |
|---|---|---|---|
| 1 | Выбор банка (с пометкой «формат не проверен») и счёта | I-1 шаг 1 | `GET /imports/banks`, `GET /accounts` |
| 2 | Выбор файла (drag & drop / кнопка) с клиентской проверкой расширения и размера ≤ 5 МБ | I-1 шаг 2 | — |
| 3 | «Загрузить» | I-1 (прогресс) | `POST /imports/{bank}/preview` (multipart) |
| 4 | Сводка: N строк, валидных, с ошибками, дубликатов; период | I-1 шаг 3 | — |
| 5 | Таблица строк с фильтром по статусу; снятие галочек со строк | I-1 шаг 3 | `GET /imports/{id}/rows?status=&limit=&offset=` |
| 6 | Флажок «Импортировать возможные дубликаты» | I-1 шаг 3 | — |
| 7 | «Импортировать N операций» | I-1 шаг 4 | `POST /imports/{id}/commit {exclude_rows, include_possible_duplicates}` |
| 8 | Итог «Импортировано N, пропущено M» → «Перейти к операциям» | T-1 | `GET /transactions` |
| alt | «Отменить» на шаге 3 | — | `DELETE /imports/{id}` |

**Сбои и восстановление:**
- 413 / `file_too_large` → «Файл больше 5 МБ»;
- 415 / `unsupported_format`, `pdf_not_supported` → «Поддерживаются только CSV и XLSX»;
- `missing_columns` / `format_mismatch` → «Файл не похож на выписку {банк}. Проверьте банк или формат»;
- `unreadable_file` → «Кодировка файла не поддерживается (нужна UTF-8 или Windows-1251)»;
- `malicious_file` → «Файл отклонён по соображениям безопасности»;
- `too_many_rows` → «Больше 5000 строк — разделите выписку по периодам»;
- `no_transactions` → «В файле не найдено операций»;
- 409 «expired» → «Срок предпросмотра истёк (24 ч), загрузите файл заново»;
- 409 «cannot be committed» → обновить статус и показать итог;
- неудачная загрузка видна в I-2 со статусом `failed`.

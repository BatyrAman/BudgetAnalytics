# Backend Gaps, Contradictions & Decisions

> Проверено по коду на коммите `e746e35`. Каждый пробел указывает экраны, которые он затрагивает, и вариант работы **без** изменения backend (если он есть).
> Backend в рамках Task 0 **не изменялся**: это список требований и рисков, а не выполненная работа.
> Приоритет: **P1** — блокирует заявленный экран или вводит пользователя в заблуждение; **P2** — ухудшает UX, есть обходной путь; **P3** — улучшение.

## 3. Требуют независимой проверки (финансовые расчёты backend)

Значения выводятся в UI как есть. Перед публичным запуском их стоит сверить с независимым расчётом (Excel или калькулятор банка) на контрольных примерах:

| Расчёт | Где в коде | Контрольный пример (из тестов backend или живого E2E-прогона) |
|---|---|---|
| Доход по вкладу с капитализацией и «хвостом» (ACT/365) | `services/finance/deposit.py` | 1 000 000 ₸ · 16 % · ежемесячно · 12 мес = 172 270,80 ₸; EAR 17,2271 % |
| Ежегодная капитализация, 2 года | то же | 1 000 000 ₸ · 14 % = 299 600,00 ₸ |
| Простые проценты | то же | 1 000 000 ₸ · 14 % · 365 дней = 140 000,00 ₸ |
| Использование бюджета (расходы − возвраты, границы месяца в `tz`) | `services/financial_summary.py` | 200 % при двукратном перерасходе |
| Норма сбережений, изменение к прошлому месяцу | `services/finance/cashflow.py`, `indicators.py` | 80,00 %; +25,00 % / −66,67 % |
| Месяцы до цели и ежемесячный взнос | `services/goals.py` | 1 000 000 / 3 мес = 333 333,33 ₸ |
| Месяцы финансовой подушки | `indicators.py` | `current_balance / average_monthly_expenses_3m` |
| Баланс счёта | `indicators.py:46-107` | Начальный остаток + поступления − списания с даты остатка |

Ожидаемые значения в тестах backend посчитаны вручную (комментарии в `tests/integration/test_mvp_gaps_api.py`, `tests/unit/finance/*`). Сверку с калькулятором конкретного банка Казахстана не делали.

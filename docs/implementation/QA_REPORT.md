### Что исправлено на этом этапе
1. «6 падающих» Vitest-тестов. Причина: таймаут 5 с под параллельной нагрузкой (в изоляции падал 1 тест). Решение: единый `testTimeout` в `vitest.config.mts` вместо локальных переопределений.
2. **Часовые пояса.** Вся логика собрана в `lib/timezone.ts` (раньше было 4 копии). Конец дня теперь `23:59:59.999999`, поэтому операция в 23:59:59.5 больше не теряется. Заодно исправлена подписка на смену часового пояса в аналитике.
3. **Иконки категорий.** Единый `components/category-glyph.tsx` вместо трёх реализаций.
4. **Диалоги подтверждения.** Единый `components/confirm-dialog.tsx` (`role="alertdialog"`, фокус, Escape, блокировка на время запроса) вместо пяти копий.
5. **Обзор: двойной запрос.** Валюта не передаётся, пока профиль не загружен, поэтому лишнего запроса в KZT больше нет.
6. **Сборка.** Ошибка prerender (`useSearchParams` без Suspense) исправлена; удалён мёртвый маршрут `app/[section]`.
7. **Вход и регистрация.** После входа пользователь возвращался на `/login`: Next закэшировал redirect, полученный при prefetch. Теперь на границах сессии выполняется полная перезагрузка (`lib/navigation.ts`), что также очищает SWR-кэш предыдущего пользователя.
8. **Безопасность.** Обход блок-листа токен-эндпоинтов прокси через закодированный слэш (раздел 8).
9. **Мобильный дашборд.** «Последние операции» были пустыми на ширине ≤ 700 px: глобальное правило CSS скрывало таблицу, а мобильного списка не было. Список добавлен, правило ограничено карточкой.
10. **Поле суммы.** Суффикс «KZT» налезал на рамку поля в форме операции.
11. **Контраст.** Токен `text/tertiary` (2,38:1) использовался для текста, хотя по `DESIGN_SYSTEM_SPEC.md` он только декоративный. 12 текстовых правил переведены на `text/secondary` (≥ 4,59:1).
12. **Имена полей.** Подсказки входили в доступное имя полей (счёт, депозит, калькулятор, описание операции); теперь они доступны как описание (`aria-describedby`).
13. **Подпись «Средние расходы за 3 месяца»** заменена на «…за 3 полных месяца», как в определении backend; прежняя подпись делала значение «0 ₸» похожим на ошибку.

- Лимиты в E2E хранятся в памяти; в production нужен Redis-бэкенд лимитера (проверить конфигурацию развёртывания).

## 13. Release Blockers

**Для закрытого пилота (RC) кодовых блокеров нет.** Все найденные дефекты, влияющие на безопасность, данные и доступность, исправлены и покрыты тестами.

**Блокеры публичной беты** (CLAUDE.md Phase 5, вне кода frontend):
1. Юридическая проверка: обработка персональных данных в РК, локализация данных, трансграничная передача в LLM.
2. Тест с реальным AI-провайдером: качество ответов, лимиты, стоимость, таймауты (NOT RUN).
3. Rate limit на Redis в production-конфигурации; проверка развёртывания.
4. Зашифрованные бэкапы и проверка восстановления; мониторинг и алерты; нагрузочные тесты (NOT RUN).
5. Восстановление пароля (K-3): без него пользователь, забывший пароль, теряет доступ.

## 14. Final Release Recommendation

**Release Candidate — ДА, для закрытого пилота** при условии ручной проверки на одном реальном iOS- и одном Android-устройстве.
**Публичная бета — НЕТ**, пока не закрыты блокеры раздела 13.

Изменения не закоммичены и не отправлены. Коммит — только после ревью владельцем.
